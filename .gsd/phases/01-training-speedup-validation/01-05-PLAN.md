# S05: Candidate acceptance and delivery

**Milestone:** M001
**Slice:** S05

**Goal:** Convert only evidence-backed successful mechanisms into separately traceable issues and dedicated pull requests.
**Demo:** Each accepted mechanism has an evidence-backed issue and a dedicated implementation PR; rejected mechanisms have documented reasons and no code PR.

## Must-Haves

- Every accepted candidate has complete matrix evidence, regression tests, a dedicated branch, an issue, and a focused PR; rejected candidates are documented without delivery artifacts.

## Proof Level

- This slice proves: human-follow-up

## Integration Closure

Accepted PRs are independently reviewable and link to immutable benchmark evidence.

## Verification

- Publish candidate verdict, evidence references, issue/PR links, and rejected-cell explanations.

<tasks>
- [ ] **T01**: Evaluate candidate evidence _(2h)_
  Review each candidate across every nuisance mode and event scale, verify resource-aware timing and equivalence evidence, and classify it as accepted, rejected, or inconclusive. Reject any candidate with a required-cell slowdown or missing proof.
  - Files: `configs/experiments`, `README.md`
  - Verify: Acceptance evaluator output and manual evidence checklist are complete.
- [ ] **T02**: Prepare successful candidate issue _(1h per candidate)_
  For each accepted mechanism, create a dedicated local issue record describing the mechanism, affected paths, benchmark evidence, acceptance criteria, and regression coverage. Do not create an issue for rejected or inconclusive candidates.
  - Files: `README.md`
  - Verify: Issue record names exactly one mechanism and links to immutable evidence.
- [ ] **T03**: Implement and verify dedicated candidate branch _(1d per candidate)_
  Implement one accepted mechanism per branch, inventory all callers and public entry points, and run meaningful enabled-feature tests including training, checkpoint restore, primary/secondary prediction, nuisance prediction, and plotting where applicable.
  - Files: `neural_networks`, `frame`, `data_tools`, `train`, `test`
  - Verify: Full relevant pytest suite, focused negative tests, and benchmark smoke check pass.
- [ ] **T04**: Request confirmation and open candidate PR _(2h per candidate)_
  Prepare the PR description with issue link, source revision, matrix results, equivalence evidence, resource/concurrency metadata, and test commands. Request explicit confirmation immediately before pushing and opening the PR; after confirmation, push the dedicated branch and open exactly one PR.
  - Files: `README.md`
  - Verify: PR contains focused diff, evidence links, test results, and no unrelated changes; move the issue record to done in the same change.
</tasks>
